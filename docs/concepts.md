# 循环与数组：为什么这样写

> 原理说明 [C]，对应已完成练习。

## 循环：维护“已经处理好的部分”

遍历数组时，`i` 是位置，`numbers[i]` 是该位置的值。例如第32题中，`i = 1` 时，`numbers[i] = 18`。题目要下标，就保存 `i`；保存固定的 `1` 只会碰巧通过某一组数据。

长度为 `n` 的数组下标是 `0` 到 `n - 1`，所以条件是 `i < numbers.length`。每次 `i++`，处理范围扩大一个元素；到 `i == n` 时结束。

判断循环是否正确，可以用一句始终成立的话：**进入下一轮前，变量准确概括已经遍历的元素。** 这叫循环不变式。核对三步：开始时成立；处理一个元素后仍成立；结束时覆盖整个目标范围。

## 筛选、计数、求和

`if` 决定哪些元素参与，更新语句决定统计什么：

| 目标 | 初值 | 命中条件后的更新 | 变量含义 |
| --- | --- | --- | --- |
| 计数 | `count = 0` | `count += 1` | 已处理元素中，符合条件的数量 |
| 求和 | `sum = 0` | `sum += values[i]` | 已处理元素中，符合条件的数值总和 |

尚未处理任何元素时，数量与总和均为0，初值因此有意义。若每轮都重新置0，就丢掉了之前的结果。

以第26题数组的前四项为例，筛选偶数：

| 当前元素 | 是否参与 | 累计数量 | 累计总和 |
| --- | --- | --- | --- |
| -4 | 是 | 1 | -4 |
| -3 | 否 | 1 | -4 |
| 0 | 是 | 2 | -4 |
| 2 | 是 | 3 | -2 |

0会增加数量，但不改变总和。计数和求和不能互相代替。

输出位置也改变含义：循环内输出是处理过程，循环外输出是最终结果。原始片段 A01 与 A02 正好体现这个区别。

## 最大值为什么从首元素开始

第30题维护的事实是：`max` 等于已处理部分的最大值。以 `values[0]` 为初值后，第一个元素已经处理，所以从 `i = 1` 继续。

新元素更大就替换，否则保留。两种情况都使 `max` 成为扩大后的范围中的最大值。

初值0不一定属于数组。对 `{-8, -3, -12, -5}`，它会一直保留0，得到错误结果；首元素初始化则得到-3。这里要求数组非空，空数组不能访问 `values[0]`。第31题的最小值遵循同样的维护方式。

## 第一次匹配与全部匹配

- 第32题从左到右扫描，第一次命中之前的位置都已排除，因此命中后可以 `break`。初值 `-1` 不属于合法下标，用来表示未找到。
- 第33题还要统计后续匹配，必须继续扫描。每次命中输出该下标，全部扫描后输出次数。

两题只有少量语句不同，停止条件却由目标决定。完整扫描 `n` 个元素需要 `n` 次判断；查找首个匹配最多需要 `n` 次，提前命中可以减少工作。
