## 按问题选择阅读入口

| 当前疑问 | 查阅位置 | 可检验的动作 |
| --- | --- | --- |
| 写不出完整程序，或看不懂报错 | 程序、变量与类型；程序运行 | 从小输入复现错误，定位第一处与预期不同的状态 |
| 条件、次数或下标总差一点 | 运算与分支；循环与状态；数组与遍历 | 写出端点两侧、零次和一次执行的预期 |
| 输入后跳过一行，或非法输入一直重试 | 字符串与输入 | 区分按词与按行，核对错误项被消费以及输入结束 |
| 一段代码越来越长，难以改动 | 方法与参数；类与对象 | 分开计算与输出，明确参数、返回值和对象状态规则 |
| 数据数量变化、需要去重或查编号 | 集合与异常 | 根据关系选 List、Set 或 Map，再核对修改与失败约定 |

语言基础可按“类型 → 运算与分支 → 循环 → 数组”串联；写完整小程序时连接“字符串与输入 → 方法”，需要长期维护状态时再连接“对象 → 集合与异常”。这些是资料之间的前置关系，不是本人的已学顺序或完成清单。

## 怎样使用示例

每个 Java 代码块独立看待。标为“完整程序”的示例按所写公开类名保存为同名文件；其余是方法内片段，可分别放入传统 `main` 中运行。不要把不同块直接拼接成一个文件。

含多个顶层类型的完整程序（如 `ObjectDemo`、`PolymorphismDemo`）请先编译，再按含 `main` 的类名启动，见[知识示例运行方法](../practice/README.md#知识示例)。源文件启动模式会选择源文件中的首个顶层类，不一定是文件名对应的公开类，规则见 [Java 25 启动器](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html#using-source-file-mode-to-launch-source-code-programs)。

先预测输出，再执行，再解释与预测不同的第一步。知识示例用于理解原理；本人原答及其核查结果统一保存在[学习记录](learning.md)。

对一个准备实际使用的功能，先用短表记录“输入 → 预期”，运行后另记实际结果；至少按适用范围选正常输入、端点、空数据和非法输入。检查成功只证明相应行为，再通过改变一个条件、独立实现核心部分或定位新错误，检验能否迁移。可以使用 IDE 和官方文档，AI 的提示、补全与解释分别记录，不把查过的章节或助手示例记成独立掌握。

完整示例之间是不同的演示，不要为了学习知识目录而一次把输入、对象、集合都接进当前练习。每次围绕一个真实障碍查阅、尝试和回到原程序；今天的任务继续以 `current.md` 为准。
